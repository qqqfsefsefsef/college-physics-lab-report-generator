# 上线指南：让别人用上这个网站

> 结论先说：**一个 1 核 1G 的云服务器 + 一个域名，30 分钟内能上线**。
> 这台机器只做两件事：发一个静态页面、跑一个 Python 脚本（识别桥）。没有数据库、没有前端构建、没有 Node。

---

## 0. 一分钟看懂架构

```
用户浏览器
   │  https://report.你的域名.com/            ← 只有 80/443 两个端口对外
   ▼
Caddy（反代 + 自动 HTTPS）
   ├── /                     → /srv/web/prototype_v2.html      静态页面
   └── /api/*  ──剥掉前缀──→  http://bridge:8732/*              识别桥（Python 标准库）
                                   │
                                   ├── 调 DeepSeek 视觉模型（识别照片里的表格）
                                   ├── core.py 算数（纯确定性代码，不碰模型）
                                   └── render_docx.py 出 docx → projects/ 下可下载
```

**关键设计**：页面和接口同一个域名（`/api` 前缀），所以**没有 CORS、不用第二个端口、不用配跨域**。页面在 https 下会自动把接口地址定成 `https://当前域名/api`。

## 1. 三条路，先选一条

| 方案 | 适合 | 花费 | 代价 |
|---|---|---|---|
| **A. 本机 + Cloudflare 隧道** | 先给几个同学试，不想买服务器 | ¥0 | 电脑得开着；地址每次变 |
| **B. 云服务器 + Docker** | 正式上线（**推荐**） | ¥30–60/月（2C2G 更稳，1C1G 也能跑） | 要买机器、备案（国内域名） |
| **C. 云服务器不带 Docker**（`install.sh`） | 不想装 Docker | 同上 | 脚本没在本机验证过，出问题要会看 systemd |

下面只详细写 **B**（其余两个在 §4、§5）。

---

## 2. 上线前你要准备的三样东西

1. **一台云服务器**：Ubuntu 22.04/24.04，1 核 1G、20G 盘足够。阿里云/腾讯云/华为云轻量应用服务器都行（新用户常有 ¥50+/年的活动）。
2. **安全组放行 80、443**（不放行就打不开；这是新手第一大坑）。
3. **（可选，但强烈建议）一个域名**：解析一条 A 记录到服务器 IP，Caddy 会自动申请免费 HTTPS 证书。没有域名就只有 `http://IP/`，能跑，但没有小绿锁。

## 3. 方案 B：Docker 上线（照着敲）

### 3.1 在你的 Windows 电脑上打包

```powershell
# 0) 打包前先自检（不联网、10 秒）：限流、清理、11 套实验、出 docx、/api 反代拓扑
python deploy\tests\verify_deploy.py
python deploy\tests\verify_proxy.py

# 1) 重新组装部署包（改过代码就重跑一次，幂等）
python deploy\build_bundle.py

# 2) 把 deploy\server 整个传上去（约 4 MB）
#    服务器上先建目录：sudo mkdir -p /opt/report && sudo chown $USER /opt/report
scp -r deploy\server\* root@你的服务器IP:/opt/report/
```

> 包里已经带好：前端 1 个 html、引擎 33 个 py、11 套实验定义与正文、13 张插图、1 个排版模板 docx。

### 3.2 在服务器上起服务

```bash
ssh root@你的服务器IP
cd /opt/report

# 装 Docker（已有就跳过）
curl -fsSL https://get.docker.com | sh

# 配置
cp .env.example .env
nano .env        # 只改一行：SITE_ADDR

docker compose up -d --build     # 第一次会拉 python/caddy 镜像，约 2–3 分钟
docker compose ps                # 两个服务都该是 running
```

`.env` 三种典型填法：

```ini
# ① 只有 IP（先跑起来看看）
SITE_ADDR=:80

# ② 有域名（自动 HTTPS，推荐）
SITE_ADDR=report.abc.com

# ③ 你替所有人付钱（危险，务必同时设口令）
SITE_ADDR=report.abc.com
DEEPSEEK_API_KEY=sk-xxxx
BRIDGE_TOKEN=给同学的口令
```

### 3.3 验收（三条命令）

```bash
curl -s http://127.0.0.1:8732/health          # 期望 {"ok":true,"mode":"real",... "experiments":[11 个]}
curl -sI http://你的服务器IP/                  # 期望 302 → /prototype_v2.html
docker compose logs --tail=20 bridge          # 看有没有 [bridge] http://0.0.0.0:8732 ...
```

浏览器打开 `http://你的服务器IP/`（有域名就是 `https://域名/`）：
- 首页出现公告 → 点「我已知晓」
- 上传一张原始数据页 → 自动识别实验名 → 核对页出选择题 → 生成 → 下载 docx

### 3.4 日常运维

```bash
docker compose logs -f web        # 访问日志（含每个请求的耗时）
docker compose logs -f bridge     # 识别/生成日志、[usage] token 台账
docker compose restart bridge     # 改了 .env 或代码后
docker compose up -d --build      # 改了代码后（重打包镜像）
du -sh data/projects              # 生成物占用；bridge 每天自动删 7 天前的
```

**备份**：`tar czf report-backup-$(date +%F).tgz data .env` → 拉回本地。
**升级**：本地重跑 `build_bundle.py` → `scp` 覆盖 `app/` → `docker compose up -d --build`。

## 4. 方案 A：不买服务器（Cloudflare 隧道）

```powershell
# 你的电脑上：装 cloudflared，然后
cd 06_网站方案
.\start.cmd -Tunnel
```

它会打印两个 `https://xxxx.trycloudflare.com`：
- 页面地址 → 发给同学（临时可用）
- bridge 地址 → 在页面右上角「连接设置」里填它

限制：电脑关机就没了；免费隧道地址每次重启都变；速度一般。**适合内测，不适合长期**。

---

## 5. 方案 C：裸机（不装 Docker）

```bash
# 服务器上，在 deploy/server 目录里
sudo bash install.sh
```

它会装 python3 + Caddy、建 venv 装 `pillow pillow-heif`、写 systemd 服务 `report-bridge`、把 Caddyfile 里的 `/srv/web` 换成 `/opt/report/app/web`。

> ⚠️ 这个脚本**没在本机验证过**（本机是 Windows）。第一次跑如果失败，看 `journalctl -u report-bridge -n 50` 和 `journalctl -u caddy -n 50`。

## 6. 钱和限额（已经内置）

| 项目 | 值 | 在哪 |
|---|---|---|
| 单份报告成本 | ¥0.02–0.08（4 次模型调用） | 结果页会显示实际用量和估算价 |
| ¥10 是什么 | DeepSeek 平台**充值最低档**，够跑 100–400 份 | 不是一份的价格 |
| 每设备限流 | 识别 8 次/分、生成 8 次/分、每 IP 每小时 200 次 | `bridge.py` 的 `RL_RULES` / `RL_HOURLY` |
| 生成物保留 | 7 天，定时自动删 `web-*` | `.env` 的 `PROJECT_KEEP_DAYS` |
| 付费模式 | **默认 BYOK**：每个用户填自己的 key，你零成本 | 页面「接入自己的 API」 |
| 统一付费 | 服务端 `DEEPSEEK_API_KEY` + `BRIDGE_TOKEN` 发口令 | 别公开贴口令，按人发 |

要扩限流：改 `RL_RULES` 里的 `(次数, 窗口秒)` 再 `docker compose up -d --build`。

## 7. 上线检查清单（逐条打勾）

- [ ] 安全组放行 80/443（腾讯云还叫「防火墙」）
- [ ] `curl /health` 返回 11 个实验
- [ ] 有域名的话：解析生效（`ping 域名` 指到服务器 IP）→ Caddy 自动签发证书（`docker compose logs web | grep -i certificate`）
- [ ] 浏览器上传真实照片能识别（**必须用你自己的 key 实测过一次**——这条目前只有桩数据验证过）
- [ ] 页脚显示的是实验名，不是「长度测量」
- [ ] 下载的 docx 用 Word 打开不报错、表格和图片都在
- [ ] PDF：现在是浏览器打印（Ctrl+P → 目标「另存为 PDF」→ 取消页眉页脚）
- [ ] `.env` 没被提交进任何仓库（里面有 key）
- [ ] 生成物目录 `data/projects` 有人看着（磁盘 20G 够用很久）
- [ ] 出问题能找到日志：`docker compose logs`

## 8. 常见故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 打不开、超时 | 安全组没放行 / 服务没起 | `docker compose ps`；云控制台放行 80/443 |
| 页面能开、生成报 502 | bridge 挂了或上游地址不对 | `docker compose logs bridge`；确认 `BRIDGE_UPSTREAM=bridge:8732` |
| 识别报「还没有密钥」 | 服务端没配 key，用户也没填 | 让用户在首页填自己的 key，或配 `DEEPSEEK_API_KEY` |
| 识别报「模型没有返回 JSON」 | 思考模式吃 token（已修） | 确认镜像是最新代码；`docker compose logs bridge` 看 `finish_reason` |
| 上传 HEIC 失败 | 镜像没装 `pillow-heif` | Dockerfile 已装；裸机则 `pip install pillow-heif` |
| 上传报 413 | 反代体积上限 | Caddy 默认无限制；若前面套了 nginx，`client_max_body_size 20m` |
| docx 里图片缺失 | `PIPE_GEN` 指错 | 容器里必须是 `/app/assets` |
| 证书一直不签发 | 域名没解析对 / 用了 IP | 先用 `SITE_ADDR=:80` 跑通再上域名 |
| 中文文件名下载变乱码 | 少数旧浏览器 | 已是 `filename*=UTF-8''`，Chrome/Edge/Safari 都正常 |
| 磁盘满 | 生成物堆积 | `du -sh data/*`；调小 `PROJECT_KEEP_DAYS` |

## 9. 可调参数一览（`.env`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `SITE_ADDR` | `:80` | 域名或 `:80`；Caddy 靠它决定是否申请 HTTPS |
| `DEEPSEEK_API_KEY` | 空 | 填了＝服务端付钱 |
| `BRIDGE_TOKEN` | 空 | 填了＝页面「连接设置」要填同一口令 |
| `PROJECT_KEEP_DAYS` | `7` | 生成物保留天数 |
| `BRIDGE_HOST` / `BRIDGE_PORT` | `0.0.0.0` / `8732` | 容器内监听；别把 8732 映射到公网 |

## 10. 还没做（上线后可以排期）

1. **账号体系**：现在是「无登录 + 口令」，适合小圈子；要给陌生人用就得加登录和每人配额。
2. **服务端出 PDF**：需要镜像里加 LibreOffice（+400 MB）；现在走浏览器打印，效果一样。
3. **对象存储**：生成物放本地卷，量大了换 S3/OSS。
4. **备份自动化**：现在是手动 `tar`，可挂 cron 到另一台机器。
5. **另 8 套实验的讲稿配图**：目前 11 套都能出报告，但只有光电/钨/杨氏带实验装置图（其它套正文里没有插图，不影响数值与排版）。
