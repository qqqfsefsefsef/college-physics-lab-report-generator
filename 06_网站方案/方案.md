# 实验报告工厂 · 前端方案（v0.1）

> 把「激光抄讲义 → 手打 64 个数据 → 三张表 → 两张图 → 排版成 Word → 导 PDF」这套已经跑通两次的流程，
> 变成一个浏览器里点点就能出报告的网站。
>
> 配套原型：`prototype.html`（单文件、零依赖，双击即开，数据可改、实时重算）。

---

## 0. 一句话定位

**面向大学物理实验课的「数据 → 图表 → 报告」流水线编辑器**：学生只负责录数据和写体会，
排版、公式、编号、误差传递、图表、docx/PDF 导出全部由程序保证。

---

## 1. 现状盘点：能直接复用的资产

这套东西不是从零开始——两次人工交付已经把「正确的样子」固化下来了。

| 资产 | 位置 | 变成什么 |
|---|---|---|
| 两份成品报告（126/128 段、5 表/4 表、7/8 图） | `05_成品_报告\*.docx` | 报告模板的**黄金样本**，逐段 diff 基准 |
| 模板骨架（评分规则页 / 页眉页脚 / 红字说明） | `03_参考模板_旧报告\热膨胀系数.docx` | 模板常量：宋体 12pt、正文色 `494949`、红字 `FF0000`、页边距 3.17/2.54cm |
| 计算脚本 | `04_生成过程_脚本图表\build_data*.py` | 抽成 **TS 计算引擎**，用两份真实数据做单元测试 |
| 排版脚本 | `04_生成过程_脚本图表\build_report*.py` | 抽成 **文档生成器**（浏览器端） |
| 图 | `figures*\*.png` | 复刻成 Canvas 绘制函数（论文式样，不用图表库） |
| 文案 | `content*.md` | 每实验一份**文案模板**（原理/步骤/体会/思考题），可编辑 |
| 讲稿与手写数据页 | `02_实验讲稿\*\`、`01_素材_*\` | 每个实验的素材包 |

**已经踩过的坑（直接变成需求）**
1. 手写数字有歧义（表 1 整行被涂改、表 2 第 8 行写在框外）→ 必须有人工核对环节，且**改动要留痕**。
2. 讲稿自身有错（h 公认值印错、两个“表 3”重号、`405.0` vs `404.7`）→ 需要**讲义勘误表**，不是硬编码。
3. 图内标题自带的“图 N”会和正文图注打架 → 图注编号必须**单点生成**（由文档序号推）。
4. 舍入决定结果：同样的数据，用全精度算 `m = −22.56`、按“表里写几位”算 `m = −22.13`（报告采用后者）→ 这条必须写进产品规则。
5. 没有 LibreOffice / Word COM → **PDF 只能用浏览器打印**，不要再设计服务端渲染。

## 2. 用户与场景

- **主用户：学生本人**（单机、单人、一学期 8–10 个实验）。目标：从 3 小时压到 30 分钟。
- **次用户：同组同学**——一键分享“实验配置 + 数据”，各自填自己的体会。
- **潜在用户：助教**——批量看哪份报告的数据不自洽（后续阶段，本期不做）。

关键约束：**作业数据是隐私**，默认全程本地，不上传服务器；要联网只用于“OCR 可选增强”。

## 3. 产品形态：四步流水线

```
① 素材  →  ② 数据  →  ③ 核对与图  →  ④ 导出
```

### ① 素材
- 拖入：讲稿截图（1–6.png）、手写原始数据页、超星得分截图。
- 输出：识别出的**表格草稿** + **疑似异常提示**（“第 8 行在表格框线外，可能是漏标行”）。
- 不做“全自动信任”：识别结果一律标黄，必须过一遍 ③ 才生效。
- 兜底：完全不识别也能用——直接手输 64 个数，30 秒。

### ② 数据
- 一张主表（实验定义决定行列），单元格可编辑，`I_a` 改动即时重算。
- 派生表（表 2 / 表 3）默认只读、灰底，鼠标悬停显示“由哪几格算出”。
- 顶部一条**数据自洽条**：行数/列数/缺项/非单调告警（如 `2.16 行缺失`、`I_a 在 −3V < −4V`）。

### ③ 核对与图
- 4 个 KPI 卡：斜率、相关系数、逸出功、相对误差（超阈值变红）。
- 两张交互图：悬停显示点值、可切换“显示/隐藏某条曲线”、可拖拽排除离群点（重新拟合）。
- **即时反查**：点图上任一点 → 高亮回表格对应单元格。

### ④ 导出
- 报告结构：模板固定的 9 节，红字说明原样保留，图注/表注编号自动。
- 导出三件套：`.docx`（主交付）、`.pdf`（浏览器打印）、`.json`（存档/分享）。
- 附「校验清单」：字数是否 ≥300、图是否 7 张、表是否 5 张、是否有空节。

## 5. 技术选型

| 关注点 | 选择 | 为什么不选别的 |
|---|---|---|
| 构建 | **Vite + React 18 + TypeScript** | 状态多、表单多、要 HMR；本机 node v24 已装 |
| 依赖管理 | **npm**（pnpm 不在 PATH） | 只有 npm 现成可用；`npm install` 需网络，离线时退回“零构建单文件”形态 |
| 样式 | **Tailwind + CSS 变量** | 界面快；但报告区**不用** Tailwind，用独立 `print.css` 精确复刻模板 |
| 图表 | **Canvas 2D 手绘**（已写 `drawFamily/drawMain`） | 论文式样要求轴刻度、字号、图注可控；ECharts 默认样式不像教材图 |
| 报告 → docx | **docx.js**（浏览器生成） | 复用 `build_report.py` 的排版参数表，逐项对齐宋体/494949/表宽 8300 twips |
| 报告 → PDF | **浏览器打印**（`@page` + print CSS） | 无 LibreOffice、Word COM 不可用；打印是唯一稳的路径（原型已验证） |
| 本地存储 | **IndexedDB（Dexie）+ JSON 导入导出** | 一份实验含图片，localStorage 容量不够 |
| OCR（可选） | 后端 `FastAPI` + 多模态模型 | 纯前端做不好手写体；做成**可选增强**，失败即降级为手输 |
| 测试 | **Vitest**，黄金样本 = 本次两份真实数据 | 计算引擎必须锁死，否则改一处全错 |

**分层**：`纯计算引擎（无 DOM）→ React 组件 → 导出器`。计算层不 import React，便于直接跑测试，也便于以后复用到 CLI/后端。

```jsonc
{
  "id": "tungsten-work-function",
  "title": "钨的逸出功测定",
  "template": { "school": "南京信息工程大学", "footer": "长度测量", "sections": ["purpose","apparatus","theory","steps","rawPhoto","analysis","summary","questions","chaoxing"] },

      "colHeader":{"label":"U_a / V","values":[25,36,49,64,81,100,121,144]},
      "cells":"editable" },
    { "id":"t2", "derived":"log10(cell:Ia)", "caption":"不同温度 T 和 √U_a 下对应的阳极电流的对数值 lg I_a", "round":2 },
    { "id":"t3", "derived":true, "caption":"lg(I_s/T²)～1/T 数据表",
      "rows":[
        {"label":"T / 10³K","calc":"T/1000"},
        {"label":"1/T (10⁻³K⁻¹)","calc":"1000/T","round":2},
        {"label":"lg I_s","calc":"intercept(fit(log10(Ia) ~ sqrt(Ua)))","round":3},
        {"label":"lg(I_s/T²)","calc":"lgIs - 2*log10(T/1000)","round":2} ] }
  ],
  "fits": [ { "id":"f1", "x":"sqrt(Ua)", "y":"log10(Ia)", "groupBy":"If", "out":"intercept" },
            { "id":"f2", "x":"1/T×10³", "y":"lg(I_s/T²)", "out":"slope" } ],
  "results": [ { "id":"work-function","label":"逸出功","expr":"2.303*k*abs(m*1000)/e","unit":"eV","compare":4.54,"digits":2,"uncertainty":"slope-se" } ],
  "figures": [ { "id":"fig4","after":"t3","type":"family","title":"lg I_a–√U_a 拟合直线族" },
               { "id":"fig5","after":"t3","type":"linear","title":"lg(I_s/T²)–1/T 直线" } ],
  "prose": { "theory":["…","[[F1]]","…"], "steps":["…"], "summary":["…"], "questions":[{"q":"…","a":"…"}] },
  "errata": [ {"where":"讲义 1.png","issue":"h 公认值印作 6.62916e-34","fix":"按 6.626e-34"} ]
}
```

要点：
- **“算式就是数据”**——`calc` 里是可求值的迷你表达式（`sqrt()`、`log10()`、`fit()`、`intercept()`），由计算引擎解释；不写死 Python。
- `round` 显式声明：**表里显示几位，就按几位参与后续计算**（这就是 `m=−22.13` 而不是 `−22.56` 的原因）。
- `errata` 让讲义的错有处可放，报告里可附“勘误说明”。

## 7. 计算引擎

三层，纯函数，输入输出可序列化：

```
Table(原始)  →  Derive(逐格变换)  →  Fit(最小二乘 + 误差)  →  Result(带不确定度、按有效数字收尾)
```

- 舍入：只在**声明了 `round` 的节点**舍入；中间量保 1–2 位多余位。
- 误差传递：斜率标准偏差 `se = sqrt(SSE/(n−2))/sqrt(Sxx)`；`u(eφ) = 2.303·k·se·1e3/e`。
- 规则化输出：`4.39 eV`、`(6.75 ± 0.91)×10⁻³⁴ J·s`、`1:3.70:14.68`——按“有效数字 + 不确定度位数”自动排版。
- **黄金测试**（必须过）：
  | 数据集 | 断言 |
  |---|---|
  | 钨 | m = −22.10±0.01，b = 12.51，r = −0.9981，eφ = 4.385 eV，E = −3.40%，u = 0.11 eV |
  | 光电 | K = 4.21355e−15，h = 6.750e−34，E = 1.87%，截距 −2.109 V |

## 8. 报告生成

**两段式**：`结构树（JSON）` → `渲染器（DOM / docx）`。同一棵树出 HTML 预览与 docx，保证“所见即所得”。

模板常量（从 `热膨胀系数.docx` 实测，直接抄）：
```
页面 A4 21.00×29.70cm；页边距 上/下 2.54、左/右 3.17；页眉 1.50 页脚 1.75
正文 宋体 12pt + Times New Roman(西文)，颜色 #494949，行距按模板
节标题 = 3 个 run：『【』+ 节名(加粗) + 『】10%』
节后说明文字：颜色 #FF0000，原样保留（评分要求“保留红字”）
表：tblW 8300 twips、表头灰底、边框单线 0.5pt、表注在上、图注在下
页眉「南京信息工程大学-大学物理实验报告」；页脚「长度测量」
```
生成后自动跑**自检**（原型里已在用）：段落/表/图计数、章节齐全、字数、是否残留占位符。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OCR 认错手写数字 | 数据错 → 报告全错 | 一律“建议值 + 人工确认”；关键格（被涂改的）标记 `suspect`；导出前强制过核对页 |
| 浏览器生成 docx 的保真度 | 字体/表格差异 | 双轨：docx.js 直出 + 打印 PDF 兜底；上线前与手工版逐段 diff，差异 >1% 不放行 |
| npm 需联网 | 离线环境装不上依赖 | M0 用零构建单文件（已有原型）；M1 起才 `npm i`，并把构建产物提交 |
| 模板版本变更（学校改模板） | 全部排版失效 | 模板常量集中在 `template/*.json`，报告不写死；版本号随文档存 |
| 通用化过度设计 | 做不出可用版本 | 先只支持这 2 个实验，用数据驱动勉强支持第 3 个时再抽象 |

## 11. 验收标准

- 新实验从“空白”到“导出 docx”：**≤ 30 分钟**（录数据 5 min、核对 3 min、体会 15 min、导出 2 min）。
- 与原手工版对比：表格数值 100% 一致；图 7 张齐全；`eφ` 相对误差 −3.4% 一致；段落结构 9 节齐全。
- 计算引擎测试覆盖：两套数据、4 种舍入组合全部通过。
- 打印 PDF：A4 页边距、页眉页脚、红字保留，逐页无断表、无孤行。

## 13. 需要你拍板的三件事

1. **范围**：先做“我这两个实验能用”，还是一开始就设计成“任何实验都能配”？
   *建议先窄后宽——M1/M2 只保这两个，M3 再抽象。*
2. **形态**：纯本地（双击 HTML / 本地 dev server，数据不出机器）还是部署到公网给同学用？
   *建议先本地，M3 再上静态托管。*
3. **OCR 要不要**：不做 OCR 就纯手输（64 个数约 30 秒），做了能省这一步但要后端和模型额度。
   *建议先不做，等 M4 再说。*

> 你可以先双击 `prototype.html` 看一眼：改表 1 任意一格，右边两张图和 `eφ` 会立刻重算——
> 这就是 M1 要工程化的那个核心。
