# 方案 v2：API 接入方式与收费模式

> 定位不变：**面向大学物理实验课的数据 → 图表 → 报告流水线**。
> 本版只回答两个新问题：① 用谁的 API；② 10 元/次怎么落地。
> 约束：只服务身边人（≤20 人量级），不做公开推广。

---

## 一、先说结论

1. **一个模型不够，要"两段模型 + 一段确定性代码"**。数字永远由代码算，模型只负责读图和写字。
2. **BYOK（他们自己填 key）和 10 元/次（你代付）不是二选一**，而是同一个产品的两个开关：愿折腾的人免费自填，不想折腾的人付 10 块。代码只差一层"谁付 token"。
3. **"上传之前做过的作业"不要做微调**，做"风格卡 + few-shot"。半小时能实现，效果够用，还能让用户自己调开关。
4. **报告生成的成败在"校对"这一步**，不在模型。一页手写数据我们实测有 9 个歧义格子；不校对就等于批量生产错误。

---

## 二、为什么必须是两段模型 + 一段代码

```
                     ┌──────────────────────────────────────────────┐
 原始数据照片 ───────▶│ ① 视觉模型：看图 → 结构化 JSON（表格单元格） │
 超星得分截图        │    deepseek-v4-flash-vision-exp 等            │
                     └──────────────────┬───────────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────────┐
                     │ ② 人工校对：逐格确认 + 低置信度格高亮        │◀── 不可省
                     └──────────────────┬───────────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────────┐
                     │ ③ 计算引擎（TS 纯函数，带单元测试）          │
                     │    拟合/截距/逐差/对称测量/不确定度          │
                     └──────────────────┬───────────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────────┐
 旧作业范文 ────────▶│ ④ 文本模型：只写文字（原理/步骤/体会/思考题）│
 实验讲稿（本地）    │    注入风格卡 + 结构化结果 + 字数要求        │
                     └──────────────────┬───────────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────────┐
                     │ ⑤ 浏览器内 docx 生成（docx.js）→ 下载/打印   │
                     └──────────────────────────────────────────────┘
```

三条硬理由：

- **可复现**：同一个数据页，两次生成必须得到同一个 4.385 eV / 4.39 eV。模型做不到，代码能做到。
- **可解释**：用户问"这数怎么来的"，站点能展开算式。这既是产品力，也是处理纠纷的凭据。
- **防幻觉**：模型一旦参与计算，就会编数（"看起来合理的 4.54 eV"），那比生成失败严重得多。

> 现有资产直接对得上：`04_生成过程_脚本图表\build_data_tungsten.py`、`build_report.py` 已经把 ③⑤ 跑通了一遍；`data_tungsten.json` 就是 ② 之后的中间态。网站只是把这条 Python 流水线译成浏览器里的 TS。

## 三、API 接入：两种模式一张表

| | 模式 A：BYOK（免费） | 模式 B：代付（10 元/次） |
|---|---|---|
| key 在哪 | 用户自己的，存在浏览器 IndexedDB | 你的，存在服务端环境变量 |
| token 谁付 | 用户 | 你 |
| 请求路径 | 浏览器 →（可选代理）→ DeepSeek | 浏览器 → 你的 Worker → DeepSeek |
| 站点成本 | ≈ 0（纯静态托管） | 每次 0.1–0.5 元（见第四节） |
| 用户门槛 | 要会申请 key、充值 | 无 |
| 适合谁 | 你自己、折腾型同学 | 大多数同学 |
| 风险 | CORS 若未放开，必须加一层转发 | key 泄露 = 直接损失，需限额与记账 |

**关键实现细节**

- 模式 A 也建议走同一个 `/api/generate`，Worker 只做转发（请求头带 `x-user-key`），这样两种模式共用一套代码，且能统一做 CORS、超时、重试、日志脱敏。
- 模式 B 必须有三样东西：**兑换码**（一次一码，`KV` 里存 `code → 剩余次数/到期`）、**限额**（单用户日上限，防脚本刷）、**账本**（谁、什么时候、生成了哪个实验、失败是否退次数）。
- 模型白名单：`deepseek-v4-flash-vision-exp` 是 **exp（实验）** 模型，随时可能改名或下线。代码里必须有 `VISION_MODELS = [...]` 数组 + 失败降级（换备用模型 → 再失败则让用户手动填表）。

## 四、成本与定价（10 元/次到底赚不赚）

按 DeepSeek 官方口径：vision 模型图片按 token 计费，**一张图最多 384 tokens**，价格与 V4-Flash 同级（[IT之家 2026-08-21](https://m.ithome.com/mip/html/992755.htm)）。

一次报告的典型消耗：

| 项 | 量 | 说明 |
|---|---|---|
| 视觉输入 | 8–16 张图 | 数据页按表切 3–4 块 + 超星截图 1 张，每图 ≤384 tokens，合计 ≤6k tokens |
| 文本输入 | 5–10k tokens | 实验定义 + 风格卡 + 结构化结果 |
| 文本输出 | 8–12k tokens | 原理/步骤/体会/思考题（约 6000–9000 字） |
| 单次成本 | **≈ 0.1–0.5 元** | Flash 级价格下的量级估算，非精确报价 |

**结论**：10 元/次是 20–100 倍毛利，token 成本可以忽略。真正的成本是**答疑与返工**——所以：

- 建议定价改成 **"10 元/次，含 2 次免费重做"**，或直接 **"30 元/学期包干"**；按次收钱会带来对账和退款的社交摩擦，包干更省事。
- 收款走微信收款码 + 你手动发兑换码（身边人量级，够用）。**不要**上支付接口——开户、对账、退款都要成本。
- 页面明码标价 + 失败自动退次数，避免"给了钱没出报告"的尴尬。

## 五、"让报告有我自己的特点"怎么做

不做微调（要数据、要训练、还要维护）。做**风格卡 + few-shot**：

1. 用户上传 1–3 份自己写过的报告（docx/pdf 均可，浏览器端用 mammoth/docx.js 抽文本）。
2. LLM 抽一次"风格画像"，输出结构化 JSON：

```json
{
  "person": "第一人称，常用「我」，不用「笔者」",
  "sentence_len": "中长句，平均 28 字，少用短句排比",
  "connectives": ["其实", "不过", "于是", "后来才发现"],
  "structure": "现象→困惑→怎么解决→得到什么",
  "taboo": ["不要写成教科书", "不要出现「综上所述」"],
  "samples": ["……", "……"]
}
```

3. 生成时把这张卡 + 2–3 段范文原文塞进系统提示词，并加一条硬约束：**不得复用范文中连续 12 个字以上**（防雷同，也是防抄袭投诉）。
4. 给用户两个滑杆：`口语 ↔ 书面`、`简洁 ↔ 详细`。

**注意**：风格卡里要放"个人信息"（学号姓名指导教师），但**只存在浏览器本地**，不上传、不入库。

## 六、隐私与合规（身边人用也要有底线）

| 数据 | 存哪 | 保留多久 |
|---|---|---|
| 原始数据照片 / 成绩截图 | 只在浏览器内存与 IndexedDB，**不传对象存储** | 用户可一键清空；默认 7 天自动清 |
| 表格数值、计算结果 | IndexedDB（本地） | 同上 |
| 风格卡与范文 | 本地 | 同上 |
| 兑换码与账本（服务端） | KV / SQLite | 只存 `码/次数/日期`，**不存学号姓名成绩** |
| 生成的 docx | 浏览器里造，直接下载 | 服务端不落盘 |

- 页面首屏写明：**"图片只在本机解析，不上传保存"** —— 这是身边人愿意用的关键。
- 学术诚信：文案统一说"数据处理与排版助手，正文请你确认后提交"，不写"代写"。小范围、不公开推广，风险可控。

## 七、里程碑（以"一周能给别人用"为准）

| 周 | 目标 | 验收 |
|---|---|---|
| W1 | 单页跑通 BYOK：上传 → 视觉读表 → 校对 → 算 → 图 → docx | 钨的逸出功一份，数值与 `05_成品_报告\钨的逸出功测定.docx` 完全一致 |
| W2 | 代付模式：兑换码 + 次数 + 账本；11 套讲稿变实验库 JSON | 用一个码跑出光伏效应报告；码第二次进入返回余额 |
| W3 | 风格卡（上传旧作业 → few-shot）+ 文案自检（≥300 字、无 12 字复用） | 同一实验、两份范文，产出语气明显不同 |
| W4 | 3–5 人试运行，收 10 元/次，记录返工率 | 返工率 <30%，单份出具时间 <25 分钟（含校对） |

## 八、现在必须拍板的四件事

1. **key 从哪来**：你有没有 DeepSeek 的 key（或用别人的试跑）？—— 这决定 W1 能不能真跑通，还是只能先做假数据。
2. **先做哪个**：① 把这个文件扩成完整施工图；② 直接把 prototype.html 升级成"真调 API 的单页"；③ 先把 11 套讲稿做成实验定义 JSON（不依赖 API，马上有内容）。
3. **定价形态**：按次 10 元（含 2 次重做） 还是 学期包干 30 元？
4. **模型路线**：只用 DeepSeek（便宜、国内直连）；还是加一个备用视觉模型（GLM-4V / Qwen-VL）做降级，防 exp 模型下线。

## 九、已知风险（按严重度）

1. **手写识别仍会错格子** —— 即使换最强视觉模型。必须保留人工校对页，且把"低置信度格子"高亮。这是我们今天在一页数据上踩到的真实坑（9 个歧义格）。
2. **384 tokens/图的上限** —— 整页照片会被压缩到看不清。必须前端按表切块再送，或只送局部。
3. **CORS** —— 浏览器直连第三方 API 常被拦。需要实测；稳妥做法是真的做一个 `/api/generate` 转发（顺带解决 key 隐藏）。
4. **exp 模型随时变化** —— 白名单 + 降级 + "手动填表"兜底，别让用户卡死在错误页。
5. **"每人一份不同的报告"是伪需求还是真需求** —— 如果老师只查数据一致性，个性化语气其实是加分项；如果老师按人查重，那就要在提示词里强制差异化（不同章节顺序、不同举例）。这一点等试运行反馈再定。
