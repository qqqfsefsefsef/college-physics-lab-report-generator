# 让别人也能用：部署操作指南

先把「谁跑在哪里」说清楚，后面所有方案都是在回答这两个问题怎么摆。

| 东西 | 是什么 | 必须跑在哪 |
|---|---|---|
| `prototype_v2.html` | 纯前端页面（一个文件，零依赖） | 任何静态托管 / 任何机器 |
| `bridge.py` | 本地 Python 服务：调模型识别、算数、出 docx | **一台装了 Python、能连 api.deepseek.com 的机器** |

关键点：**审核那张照片的活是在 bridge 那台机器上干的**，所以别人要能用，就得让「他们的浏览器」能连到「你的 bridge」。

---

## 〇、最快上手（推荐先这么干）

`06_网站方案` 里现在有两个一键文件：**`start.cmd`（双击即可）** 和它背后的 `start.ps1`。

| 你想怎么测 | 双击什么 | 会发生什么 |
|---|---|---|
| 自己先看看 | `start.cmd` | 只本机可用，自动开浏览器 |
| 室友试界面（不花钱） | `start.cmd -Mock -Lan` | 桩模式：不联网、不耗额度，全流程都能点（识别结果是内置的示例数据，报告会标「示例数据」） |
| 室友试真识别 | `start.cmd -Lan` | 真识别，但要有人填 key（他们自己填，或你在这台机器上配） |
| 发给外地的人 | `start.cmd -Tunnel` | 用 cloudflared 打隧道，生成两个公网 https 地址 |

`-Lan` 会直接把要发的话打印出来，例如：

```
发给室友的地址：
  http://10.0.230.84:8731/prototype_v2.html
  「连接设置」里填： http://10.0.230.84:8732
```

**局域网模式下其实「连接设置」都不用填**——页面会自动把 bridge 猜成 `http://<当前地址>:8732`。只有 `-Tunnel`（https 页面）才必须手动填一次。

> 第一轮内测强烈建议用 `-Mock -Lan`：朋友不填 key 也能把 11 个实验的流程走完，你也不花钱，还能收集界面反馈。

## 一、三种方案，按成本从低到高

| 方案 | 谁能用 | 月成本 | 代价 |
|---|---|---|---|
| **A 本机 + 局域网** | 同一个 WiFi 里的室友 | **¥0** | 你的电脑得开着；只能内网 |
| **B 家里电脑 + Cloudflare Tunnel** | 拿到链接的任何人都行 | **¥0**（可选域名 ¥60/年） | 你的电脑得开着 |
| **C 云服务器** | 任何人 | **¥30–60/月**（学生机 ¥10 起） | 要维护一台小服务器 |

先 A → 再 B → 稳定了再 C。**不建议一上来买服务器**：现在还没有真实用户量，B 已经能做到「别人点开链接就能用」。

## 二、方案 A：宿舍局域网（最快，5 分钟）

```powershell
# 1) 桥绑到所有网卡（默认只听 127.0.0.1，别人连不上）
cd C:\Users\lidey\Desktop\实验报告制作沙盒\07_流水线
python bridge.py --host 0.0.0.0

# 2) 静态页也对外开放
cd C:\Users\lidey\Desktop\实验报告制作沙盒
python -m http.server 8731 --bind 0.0.0.0 --directory 06_网站方案
```

拿到你的内网 IP：`ipconfig` 里的 IPv4（形如 `192.168.1.7`），别人访问：

```
http://192.168.1.7:8731/prototype_v2.html
```

Windows 第一次会弹防火墙，**允许专用网络**；没弹就手动放行 8731、8732 两个端口。

⚠️ 这一步有个坑：页面里 bridge 地址目前写死 `127.0.0.1:8732`，在别人电脑上会指向他自己。见第五节第 1 条。

## 三、方案 B：Cloudflare Tunnel（零成本，推荐给别人用）

思路：静态页扔到免费的 Cloudflare Pages，bridge 用隧道暴露出去，浏览器两边都能 HTTPS 访问。

```powershell
# 1) 装一次
winget install --id Cloudflare.cloudflared

# 2) bridge 照常本机跑（不用开 0.0.0.0，隧道会转进来）
cd C:\Users\lidey\Desktop\实验报告制作沙盒\07_流水线
python bridge.py

# 3) 另开一个终端，临时隧道（拿到一个 https://xxx.trycloudflare.com）
cloudflared tunnel --url http://127.0.0.1:8732
```

静态页：把 `06_网站方案` 这个文件夹拖进 Cloudflare Pages「直接上传」，得到 `https://xxx.pages.dev`。

然后改页面里的 bridge 地址（第五节第 1 条），填隧道那个 https 地址。

- 隧道地址每次重启都会变 → 用 `cloudflared tunnel create` 建一条命名隧道绑自定义域名，地址就固定了。
- 好处：不用公网 IP、不用买服务器、证书自动、key 也不离开你的机器。
- 代价：**你这台电脑得开着**（睡眠就断）。

## 四、方案 C：云服务器（长期稳定）

最低配够用：**2 核 2G、20G 盘**。学生机 / 新用户价常见 ¥10–30/月，正常价 ¥30–60/月。

```bash
# Ubuntu 22.04 起手
apt update && apt install -y python3.12 python3-pip python3-venv caddy
useradd -m app && su - app

# 只装运行用的包（注意：本机沙箱装不上，服务器上没这个限制）
pip install numpy pillow python-docx

# 上传项目（本地执行）
scp -r 07_流水线 06_网站方案 app@服务器IP:/home/app/

# 起服务（建议用 systemd 而不是 nohup）
python3 bridge.py --host 127.0.0.1 --port 8732
```

Caddy 一行反代 + 自动 HTTPS（`/etc/caddy/Caddyfile`）：

```
api.你的域名.com {
    reverse_proxy 127.0.0.1:8732
}
```

静态页可以同机 `python -m http.server 8731` + Caddy 另一个站，也可以继续放 Pages（更省事）。

**服务器要能出网到 `api.deepseek.com`**（国内机器一般没问题）。key 通过环境变量给：

```bash
export DEEPSEEK_API_KEY=sk-...
```

## 五、上线前还差的两件事（其余已经做完）

**已经做完的**（`2026-10-29` 这轮改的）：

- ✅ **bridge 地址可配置**：页面右上角「连接设置」可以填地址和口令，存在 `localStorage`（`dsh.bridge` / `dsh.token`）；不填时默认 `http://127.0.0.1:8732`，如果页面本身不是从 localhost 打开，会自动猜成 `http://<当前主机名>:8732`。
- ✅ **访问口令**：`bridge.py` 读环境变量 `BRIDGE_TOKEN`，设了之后所有 `POST` 都要带 `X-Token`，否则回 401 并提示去「连接设置」填。页面会把口令自动加进每个发往桥的请求。
- ✅ **监听地址**：`python bridge.py --host 0.0.0.0`（或 `BRIDGE_HOST=0.0.0.0`）对局域网开放，默认只听本机。
- ✅ **花费可见**：结果页显示「本次用量 X tokens · 按官网价估算约 ¥0.0x」。

**还没做、上线前建议补的**：

1. **项目目录自动清理**。`07_流水线\projects\web-*` 每生成一次就多一个目录，长期跑会撑爆。
   做法：启动时删掉 7 天前的 `web-*`，`_hw`（旧作业）只保留最近 20 份。
2. **限流**。同 IP 每分钟最多 3 次 `/render`，防误点连击把额度刷光。
   做法：`Handler` 里加一个 `defaultdict(list)` 时间戳队列即可。

## 六、成本：一份报告到底多少钱

| 环节 | 调用 | 大约 tokens |
|---|---|---|
| 识别实验类型 `/detect` | 1 次 | ≤300 |
| 识别表格 `/recognize` | 1 次（图 ≤384/张） | ≤6k |
| 计算 + 排版 | **0 次**（纯本地代码） | 0 |

单份 ≈ **¥0.02–0.08**。¥10 充值大概能跑 **100–400 份**。

> 为什么「你用我生成一份要 1 块多」：那是对话模式，几十次请求、每次都重发很长的历史；管线只有 4 次调用，不背历史。

## 八、坦白：现在还不能直接扔给别人用的原因

1. 还没跑过**真实 key 的识别**——所有链路都是用桩数据验证的，真照片只验过一次（HEIC 转码那步是真的，模型那步没通）。
2. bridge 地址写死、没有访问口令、没有限流（上面第五节）。
3. 11 套讲稿目前只接了 3 套（另外 8 套正在接）。
4. `review.html` 只能看不能点，核对全靠页面里的选择题。

所以路线应该是：**先把 1、2 补掉 → 自己用一周 → 再给 3–5 个同学内测（方案 B）→ 稳定了再上服务器。**
